# Экран по макету

Макеты лежат в `design/` — это PNG-скриншоты из Figma, а не сам файл Figma
(старый прототип `App Prototyping` неактуален, ссылаться на него нельзя).
Ширина всегда 440 при `devicePixelRatio: 1.0`, то есть **один пиксель PNG = одна
логическая точка Flutter**. Поэтому по макету можно снимать координаты и
подставлять их в код напрямую.

Высота бывает двух видов: 956 — экран целиком помещается на устройство;
больше — страница прокручиваемая и макет показывает её развёрнутой.

## Порядок

1. Снять размеры с макета скриптами (ниже).
2. Свёрстать, забирая цвета/радиусы/тени из `lib/core/theme/*`.
3. Отрисовать свой экран в PNG и замерить его теми же скриптами.
4. Свести расхождения до нуля по ключевым краям.
5. Закрыть golden-тестом.

Шаг 3 — не формальность. Глазами расхождение в 30 px по горизонтали не
видно, а тест на Windows его поймает, и разбираться придётся уже по артефакту
из CI.

## 1. Замеры по макету

Скрипты в `scripts/` рядом с этим файлом — чистая стандартная библиотека,
ставить ничего не нужно. Запускать из папки со скриптами, чтобы работал
`import png`:

```bash
cd .claude/skills/screen-from-mockup/scripts && python3 png.py ../../../../design/Главная.png
```

- **`png.py`** — декодер. Отдельно полезны `row_runs` / `col_runs`: разбивают
  строку или столбец на участки одного цвета. Так снимаются отступы, высоты
  полос, границы карточек и их радиусы.
- **`ink.py`** — `report(img, x0, y0, x1, y1, bg, label)` разбивает область на
  строки содержимого и печатает bbox каждой. Это основной инструмент: даёт
  точные x и y текста, иконок, кнопок.
- **`crop.py`** — вырезает кусок макета в отдельный PNG, при желании с
  увеличением. Нужен, когда надо посмотреть на мелкую деталь глазами:

```bash
python3 crop.py ../../../../design/Главная.png /tmp/crop.png 20 400 420 480 3
```

Типовой сеанс замеров пишется одним скриптом в скретчпаде: импортировать
`Png`, `report`, `row_runs` и напечатать всё нужное разом.

## 2. Кегль подбирается по ширине краски

Главная ловушка. Высота прописных букв на макете **завышена сглаживанием на
10–15 %** — если подбирать `fontSize` по ней, текст выйдет мельче нужного и
разъедется по ширине.

Правильно: замерить `ink.py` ширину строки на макете, затем отрисовать ту же
строку своим стилем и сравнить **ширину краски**. Ширина набирается из десятков
букв, ошибка сглаживания усредняется и не мешает. Подгонять `fontSize` до
совпадения ±1 px, потом заносить в `AppTypography`.

Шрифт один — GolosText (variable), грузится в тестах через `loadAppFonts`.

## 3. Снимок своего экрана

`scripts/render_screen.dart` — шаблон. Скопировать в `test/`, вписать экран и
`overrides`, запустить, замерить полученный PNG теми же скриптами, удалить.

**Не делать этого через `flutter test --update-goldens`**: на macOS это
перезапишет эталоны, снятые на Windows. Шаблон просто пишет PNG в `/tmp`.

## 4. Ловушки вёрстки

Все — из уже случившихся расхождений на этом проекте:

- **Кнопки в `Row` сжимаются по высоте.** `Row` по умолчанию центрирует детей
  по поперечной оси, и кнопка получает свою минимальную высоту вместо заданной
  (было 35 вместо 61). Ставить `crossAxisAlignment: CrossAxisAlignment.stretch`.
  То же касается чипов в шапках.
- **`Column` съезжает влево.** Колонка обжимается по самому широкому ребёнку и
  центрируется как целое, из-за чего кнопка уезжала на 35 px. Лечится
  `crossAxisAlignment: stretch` плюс `Center` снаружи.
- **`Spacer` — не отступ.** Долями `Spacer` попасть в макет нельзя. Вертикаль
  набирается замеренными `SizedBox`; константы выносить в `<Screen>Metrics` с
  комментарием, откуда число.
- **Отступ считается по краске, а не по рамке.** У иконки внутри SVG есть поля,
  поэтому «иконка на x 47» — это край краски; чтобы совпало, отступ в коде
  будет меньше на величину этих полей. Комментировать замер целиком:
  `// Замер по design/Главная.png: краска облачка 19×19, начинается на x 47`.
- **Радиусы и тени — из токенов.** `AppRadius`, `AppShadows`; замеренное по
  макету число сверять со шкалой, а не заводить пятый радиус.

## 5. Куда класть код

Feature-first: `lib/features/<фича>/presentation/{screens,widgets,providers}`.
Экран — один файл, крупные блоки — отдельные виджеты рядом в `widgets/`,
константы вёрстки — в `<фича>_metrics.dart`. Маршрут добавляется в
`lib/core/router/routes.dart` и `app_router.dart`.

Модель, понадобившаяся второй фиче, переезжает в `lib/shared/models/`.

## 6. Эталон

Golden-тест рядом с остальными тестами фичи, файл эталона — в `goldens/`:

```dart
@Tags(['golden'])
library;
```

Размер вида и `padding` — как в макете. Репозитории подменяются синхронными
фейками из `test/helpers/`: `Future.delayed` создаёт таймер вне `runAsync`, и
тест падает на «timersPending». Анимированные GIF выключаются флагом
(`animated: false`) по той же причине.

Сам эталон **на macOS не снимается**. Снять его можно только на Windows —
запустить CI с галкой `update_goldens` и забрать артефакт `goldens`:

```bash
gh workflow run ci.yml -f update_goldens=true
```

Пока эталона нет, экран всё равно проверяется обычным виджет-тестом на
наличие ключевых элементов — это ловит опечатки в текстах и упавшие провайдеры.
